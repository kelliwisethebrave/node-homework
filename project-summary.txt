Extra back-end feature: Recycle Bin

Changes:

Add trash field to the Task model and database migration
Update deleteTask to soft delete tasks
Add permanentlyDeleteTask function and route
Add restoreTask function and route
Add emptyTrash function and route
Update index to view active or trashed tasks
Update show and update to prevent access to trashed tasks

DELETE /api/tasks/

deleteTask has been updated to soft delete tasks instead of permanently deleting them. The path remains the same (/api/tasks/:id), but it now updates the task's trash field to true.

DELETE /api/tasks//permanent

permanentlyDeleteTask permanently deletes an individual task from the database after verifying that the task is already in the Recycle Bin.

PATCH /api/tasks//restore

restoreTask restores a task by setting its trash field to false, allowing the task to be viewed and modified normally again.

No request body is required.

DELETE /api/tasks/trash

emptyTrash permanently deletes all tasks marked as trash: true that belong to the logged-in user.

GET /api/tasks?trash=true

index normally excludes tasks in the Recycle Bin. Adding the ?trash=true query parameter returns the logged-in user's trashed tasks instead.

GET /api/tasks/
PATCH /api/tasks/

show and update have been updated so that tasks in the Recycle Bin cannot be accessed or modified through the normal task routes.
