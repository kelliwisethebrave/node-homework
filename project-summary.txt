Extra back-end feature: Recycle Bin


Add trash field to Task model and database migration
Update deleteTask to soft delete tasks
Add permanentlyDeleteTask function and route
Add restoreTask function and route
Add emptyTrash function and route
Update index to view active or trashed tasks
Update show and update to prevent access to trashed tasks



DELETE /api/tasks/:id
deleteTask has been updated to soft delete tasks instead of hard delete.
The path remains the same (/api/tasks/:id) but now updates the trash field to true. 

DELETE /api/tasks/:id/permanent
permanentlyDeleteTask has been added, and after verifying that a task is in the trash, it will delete the task from the database.

PATCH /api/tasks/:id/restore
restoreTask has been added, which marks the trash field as false, and allows the task to be viewed and used by functions as normal.
No request body required.

DELETE /api/tasks/trash
emptyTrash has been added, which hard deletes all of the tasks marked as trash which belong to the logged-in user.

GET /api/tasks?trash=true
index has been updated, to normally hide tasks in the Recycle Bin, and to also show them when ?trash=true is added to the route.

show and update have been updated to prevent access to tasks in the Recycle Bin.
